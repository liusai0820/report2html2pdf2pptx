# 专业 Prompt 系统设计文档

## 设计理念

本系统基于顶级咨询公司（麦肯锡、BCG、贝恩）数十年的方法论积累，结合演示文稿设计的最佳实践，打造真正能生成高质量内容的 AI 提示词系统。

### 核心原则

1. **内容为王** - 结构清晰、逻辑严密、数据支撑
2. **一页一观点** - 每页只传达一个核心信息
3. **行动导向** - 标题即结论，内容即证据
4. **视觉服务内容** - 设计服务于信息传达

## 方法论体系

### 1. 金字塔原理 (Pyramid Principle)

麦肯锡的核心思维框架：

```
        结论
       /    \
    论据1   论据2
   /  \     /  \
 证据 证据 证据 证据
```

**应用规则：**
- 结论先行：先说结论，再说论据
- 以上统下：上层是下层的总结
- 归类分组：同层观点属于同一范畴
- 逻辑递进：按逻辑顺序排列

### 2. MECE 原则

- **Mutually Exclusive**：各部分相互独立，不重叠
- **Collectively Exhaustive**：所有部分完全穷尽，无遗漏

### 3. SCQ/SCQA 框架

构建有说服力的叙事结构：

- **S (Situation)**：背景 - 稳定的现状
- **C (Complication)**：冲突 - 打破现状的变化
- **Q (Question)**：问题 - 核心待解决问题
- **A (Answer)**：答案 - 解决方案/建议

### 4. 行动标题原则

**错误示例 ❌**
- "市场分析"
- "竞争格局"
- "发展建议"

**正确示例 ✅**
- "市场规模 5 年 CAGR 达 23%，正处于爆发期"
- "头部三家企业占据 70% 份额，竞争格局已定"
- "建议聚焦细分赛道，避开正面竞争"

### 5. So What 原则

每一页都要回答：这意味着什么？我们应该怎么做？

```
数据/事实 → So What? → 发现/洞察 → So What? → 结论/建议 → 行动
```

## 场景化设计

### 咨询研究/汇报类

**受众特点：**
- 决策者、管理层
- 时间有限，需要快速抓住重点
- 关注数据和可执行建议

**内容重点：**
- 数据驱动的分析
- 清晰的问题诊断
- 可执行的建议
- 实施路径和风险

**表达风格：**
- 专业、严谨
- 简洁有力
- 数据说话

**报告结构：**
1. 执行摘要 (1-2页)
2. 背景与目标 (2-3页)
3. 现状分析 (5-8页)
4. 解决方案 (5-8页)
5. 实施计划 (3-5页)

### 年终述职/总结类

**受众特点：**
- 上级领导、HR
- 关注成果和价值
- 评估能力和潜力

**内容重点：**
- 成果量化（数据说话）
- 个人贡献突出
- 问题反思和成长
- 未来规划

**表达风格：**
- 自信但不自大
- 务实但有亮点
- 谦虚但不卑微

**报告结构：**
1. 开场 (1页) - 一句话总结
2. 目标回顾 (1-2页)
3. 成果展示 (5-8页)
4. 经验总结 (2-3页)
5. 明年规划 (3-5页)

### 公司/项目介绍类

**受众特点：**
- 潜在客户、投资人、合作伙伴
- 需要快速了解你是谁
- 关注能带来什么价值

**内容重点：**
- 差异化定位
- 核心优势（有证据）
- 成功案例
- 行动号召

**表达风格：**
- 专业自信
- 客户视角
- 简洁有力

**报告结构：**
1. 开场 (1页) - 一句话定位
2. 公司概览 (2-3页)
3. 业务介绍 (3-5页)
4. 优势与案例 (3-5页)
5. 合作机会 (1-2页)

### 学术研究/答辩类

**受众特点：**
- 学术同行、评审专家
- 关注研究的严谨性
- 评估学术贡献

**内容重点：**
- 研究问题清晰
- 方法论严谨
- 贡献明确
- 局限性坦诚

**表达风格：**
- 严谨准确
- 客观中立
- 术语规范

**报告结构：**
1. 引言 (2-3页)
2. 文献综述 (2-3页)
3. 研究方法 (2-3页)
4. 研究发现 (5-8页)
5. 讨论与结论 (3-5页)

### 创意/营销类

**受众特点：**
- 客户、消费者
- 需要被打动
- 关注创意和效果

**内容重点：**
- 深刻的洞察
- 有记忆点的创意
- 可执行的方案
- 可衡量的效果

**表达风格：**
- 有感染力
- 有画面感
- 有记忆点

**报告结构：**
1. 引爆点 (1页)
2. 洞察 (2-3页)
3. 创意概念 (2-3页)
4. 执行方案 (5-8页)
5. 预算与效果 (2-3页)

## 质量检查体系

### 检查维度

1. **结构完整性**
   - 是否有标题
   - 是否有内容区域
   - 是否有结论框

2. **内容质量**
   - 标题是否是结论
   - 是否有空洞表述
   - 是否有 Emoji

3. **逻辑严密性**
   - 是否有逻辑跳跃
   - 是否有重复内容
   - 是否有 So What

4. **数据规范性**
   - 数据是否有来源
   - 数据是否有具体数值
   - 数据是否服务于论点

### 常见问题检测

| 问题类型 | 检测规则 | 建议 |
|---------|---------|------|
| 主题式标题 | 匹配"XX分析"、"XX介绍"等模式 | 改为结论式标题 |
| 空洞表述 | 匹配"我们可以看到"、"众所周知"等 | 删除，直接说结论 |
| 缺少 So What | 检测是否有 bottom-box | 添加结论框 |
| 数据无来源 | 有数据但无来源标注 | 添加数据来源 |
| Emoji | 检测 Unicode Emoji | 删除 Emoji |

## 使用指南

### 基本用法

```python
from prompts import create_prompt_engine

# 创建引擎
engine = create_prompt_engine(
    scenario="consulting",
    user_config={
        "organization": "深圳国家高技术产业创新中心",
        "project_name": "河套合作区研究",
        "target_pages": 30,
    }
)

# 生成系统提示词
system_prompt = engine.generate_system_prompt()

# 生成大纲提示词
outline_prompt = engine.generate_outline_prompt(document_content, target_pages=30)

# 生成页面提示词
page_prompt = engine.generate_page_prompt(page_num, total_pages, page_data)
```

## 最佳实践

### 1. 选择正确的场景

不同场景有不同的表达方式，选择正确的场景是第一步。

### 2. 提供充分的上下文

用户配置越详细，生成的内容越精准：
- 汇报单位
- 项目名称
- 目标受众
- 主题关键词
- 内容深度

### 3. 迭代优化

生成后使用质量检查器检查，根据建议优化内容。

### 4. 人工审核

AI 生成的内容需要人工审核，特别是：
- 数据准确性
- 逻辑严密性
- 表达恰当性

## 技术架构

```
prompts/
├── __init__.py           # 模块入口
├── prompt_engine.py      # Prompt 引擎
├── scenario_prompts.py   # 场景化提示词
├── methodology.py        # 方法论
└── quality_checker.py    # 质量检查器
```

### 核心类

- **PromptEngine**: 智能生成提示词
- **QualityChecker**: 检查内容质量
- **QualityIssue**: 质量问题数据结构

### 数据结构

- **SCENARIO_PROMPTS**: 场景提示词注册表
- **METHODOLOGIES**: 方法论集合
- **REPORT_STRUCTURES**: 报告结构模板

## 扩展指南

### 添加新场景

1. 在 `scenario_prompts.py` 中添加新的场景提示词
2. 在 `SCENARIO_PROMPTS` 中注册
3. 在 `get_scenario_info` 中添加场景信息
4. 在 `methodology.py` 的 `REPORT_STRUCTURES` 中添加报告结构

### 添加新方法论

1. 在 `methodology.py` 中定义新方法论
2. 在 `METHODOLOGIES` 中注册

### 添加新检查规则

1. 在 `quality_checker.py` 中添加检查方法
2. 在 `check_page` 或 `check_outline` 中调用
